## More Detail

- **Order.** Governance first (Phases 1 and 2), so the code is written under the rules it follows; each source module
  lands with its tests and its part of `architecture.md` in the same phase.
- **Not touched.** `OUTPUT_TARGET.md` and the figures in `MOVEMENT.md`: the code must reproduce them. A disagreement
  stops work for the owner's decision (recovery item RC1).
- **Already landed.** The assessment-doc resolutions this plan's review added (AMB-014, AMB-026, AMB-034, AMB-035, and
  REJECTED's abandoned approach) and the worklog rule in `assessment-docs.md` are committed before the plan, as their
  own themes, so the plan builds on them rather than proposing them.
- **Evidence.** Every record is inline under its delivery item; no file under `evidence/` is planned. One would be
  added, with its item citing it, only for an output longer than about twenty lines.
- **Generated adapters.** No file under `.agents/` changes. Editing `AGENTS.md` still changes the digests the adapters
  under `.claude/`, `.codex/`, and `.opencode/` record, so Phases 1 and 2 ran `npm run generate:bindings` (learning L2).
